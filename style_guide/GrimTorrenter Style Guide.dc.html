Everything arrives eventually

Torrent clients look like 2006.
This one won’t.

GrimTorrenter is a responsive web client for a job that is mostly waiting. The interface’s only real work is answering four questions at a glance — what is running, how fast, how far along, what needs me — so this guide optimises for scanning density over decoration. Everything below is drawn from the Industry system: square corners, hairline rules, registration marks, one steel accent.

01

Color & theming

One steel accent carries every active state. Torrent status is encoded by ramp step and glyph, not by hue — a five-color status legend is exactly the noise that makes existing clients unreadable. There is a single chromatic exception: alarm, used only where the user must act.

{{ r.name }}
{{ r.token }}

Accent ramp

{{ s.step }}

Do

  • Reserve saturated accent for the one thing in motion — the progress fill, the active tab, the primary action.
  • Keep the ground quiet: a torrent list is 90% inert rows.
  • Ship dark as a first-class theme, tokens only — no bespoke dark layouts.

Don’t

  • Never color-code the six torrent states. Two hues maximum on any screen.
  • No green “seeding” badge. Seeding is the resting state, not a celebration.
  • No gradients, no glow, no colored row backgrounds.
02

Grid, spacing & density

Compact/pro is the default: a 34px row, 4px base rhythm. Below 720px the app switches to a stacked card list and every control grows to a 44px hit target — density is a desktop affordance, not a mobile one.

04

Icons

Lucide at stroke-width 1.5. Two sizes only: 16px inline in rows, 18px in toolbars. Icons never carry meaning alone in a row — they pair with a text label or a tooltip.

The mark

An hourglass reduced to two triangles — solid, square-shouldered, drawn on the same grid as the registration marks. It is the only piece of brand imagery. Never outlined, never tilted, never animated.

Mortal set
{{ m.label }}

Reserved for identity and empty states — the skull marks the app, the hourglass marks waiting. They never appear in a torrent row: a list of skulls is decoration, and decoration is what we are fixing.

05

Buttons & controls

One primary per view — it is always Add torrent. Row-level actions are ghost icon buttons that only gain a border on hover; a row of eight bordered buttons is visual noise at 34px.

06

The torrent list

The whole app, really. Rows are 34px, separated by an 8%-ink hairline rather than zebra fill. The name column truncates from the middle so file extensions survive. Progress lives inside the row as a full-height underlay, not as a separate bar column — the row itself fills up.

Rules

  • Idle numbers dim to 35% opacity instead of showing 0.0 B/s. Zeroes are noise.
  • ETA is human (4h 12m), never ∞. Unknown reads “stalled”.
  • Selection is a 2px accent left edge, never a filled row.
  • Sort persists per view; the sorted column header takes the accent.

08

Dialogs & menus

One level deep, always. If a dialog needs a second dialog, it is a settings page. Destructive confirmations name the consequence in the button, never “OK”.

Remove 3 torrents?
They stop seeding immediately. Downloaded files stay on disk unless you also delete data.

09

Empty & error states

No illustrations, no mascots. An empty state is a drawn frame, one sentence of plain language, and the action that resolves it. Errors say what happened, what it means, and what to do — in that order.

Lexicon — where the reaper is allowed to speak

The theme lives in chrome, empty states and marketing surfaces. It never touches a status cell, a number or an error — a user staring at a stalled 40 GB download does not want a joke about mortality.
